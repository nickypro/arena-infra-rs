# Feature map — `nickypro/arena-infra` (legacy) → `arena-infra-rs`

Parity tracker between the legacy Python/bash scripts and the Rust rewrite
(`arena` CLI + `arena-tui`), as of phases 0–4. Legend: ✅ ported · 🟡 partial · ❌ missing ·
➕ new (no legacy equivalent).

Every fleet command picks pods with **one selector syntax** (`arena_core::selector`): bare
`apple`, full `arena8-apple`, absolute `@james-gpu`, provider ids, ranges `apple..mayor`
(`MACHINE_NAME_LIST` order), `all`/`--all`, narrowed by `--exclude <targets>`, `--gpus N`,
`--on <provider>`. Typos and selections that narrow to nothing are errors; `run`/`cp`
take the targets as `-t` (`pull` takes them positionally now, its label as `--label`). The TUI marks pods with the same syntax (`/`). "Selector" below
means this.

## Config keys added in phases 0–4

| Key | Default | What it does |
|---|---|---|
| `RUNPOD_API` | `v1` | RunPod REST API: `v1` (RunPod retires it 2026-11-15) or `v2`; anything else is an error. Settable from the environment (`RUNPOD_API=v2 arena pods list`). |
| `SSH_PROXY_RELOAD_CMD` | absent → `nginx -t && nginx -s reload` | Run after a proxy write; **empty = write-only** (never reloads nginx). Settable (empty) from the environment, as the sandbox wrapper does. |
| `SETUP_TIMEOUT_SECS` | 300 (image pods) / 1800 (Hetzner script) | The main setup step's budget, 1..86400, for `setup`, `up`, `restart`, `replace`, `migrate copy`; `setup --timeout` wins. Checked before `up` creates anything. |
| `ARENA_STATE_DIR` | `${XDG_STATE_HOME:-~/.local/state}/arena` | Root of the health cache and the balance state, `<dir>/<prefix>/health.json` and `balance.json` (absolute path). Settable from the environment, so a cron job and the operator can share one. |
| `BACKUP_TIMEOUT_SECS` | 7200 (2 h) | Wall-clock budget per pod for the backup rsyncs (`pods pull`, `pods backup`'s file step), 1..86400; on top of rsync's `--timeout=300` (I/O silence). A pod that runs out is stopped and named; the others finish. A malformed value fails the command before anything is copied. Settable from the environment. |
| `BALANCE_UNPRICED_PER_GPU` | 8 | The ceiling USD/h per GPU for a running pod nobody priced whose GPU type is unknown (not in RunPod's recorded catalog, the presets or a live price seen; a MIG slice of such a GPU; no type) — above the dearest recorded catalog price (B300 secure $7.89), so it errs high (burn `~$X/h`, "unknown GPU type, priced at the ceiling"). A known GPU stands in at the most it is known to cost. Must be finite, > 0, ≤ 1000; malformed: 8 is used, `arena balance` says so, `config check` ✗ and fails ("missing or invalid keys"). Settable from the environment. |
| `BALANCE_WARN_HOURS` | 72 | Prepaid runway (hours) under which an account is **low** (under 24 h it is critical). `0` turns both runway levels off (≤ $0 and RunPod's `underBalance` stay critical). A malformed value uses 72: `arena balance` says so, `config check` marks it ✗ and fails ("missing or invalid keys"), nothing else breaks. Settable from the environment (`BALANCE_WARN_HOURS=100000 arena balance --check`). |
| `REAP_ENABLED` | unset (off) | `1` lets `pods reap run --apply` act. **File-only** like every `REAP_*` key: the environment can neither set nor override it. Anything but 1/0/unset is an error. |
| `REAP_MAX_PER_RUN` / `REAP_MAX_PER_DAY` | 1 / 10 | Terminate attempts per run (1..5; `--max` only lowers it) and per rolling 24 h (1..50), counted at the write-ahead (a killed run counts). Out of range = error, never clamped. |
| `REAP_IDLE_FLOOR_MINS` | 120 | The smallest `--idle-after` (15..1440; the sandbox sets 15). Suggested cohort window: ~8 h. |
| `REAP_MIN_FREE_GB` | 20 | Free space each backup tier root needs before a reap backup (1..100000). |
| `REAP_NOTIFY_CMD` | unset (cron log only) | `sh -c` command fed one sanitized line per notification on stdin, killed after 10 s; its failure changes nothing. |
| `LOCAL_BACKUP_BIG_DIR` | `<LOCAL_BACKUP_DIR>/big` | The big (all-files) tier's root — its own volume. When set, `pods pull`/`backup` require the `.arena-backup-tier` markers on both roots (`snapshot` / `big`); `pods restore --from big` reads it. The reaper always requires the markers. |
| `CREATE_EXTRA_JSON` | unset | One JSON object (single-quoted) deep-merged into every create request body — `create`/`up` (`--api-json` merges over it), the TUI's add-pod form, `replace`/`migrate copy`'s replacement. Fields arena sets itself (and templates) are refused before any call. |

| `ARCHIVE_HETZNER_API_KEY` | `HETZNER_API_KEY` (with a warning) | The backup archive's Hetzner token — its own project recommended. `archive sync` (the cron path) never needs it. |
| `ARCHIVE_LOCATION` / `ARCHIVE_SERVER_TYPES` | `HETZNER_LOCATION`, else `nbg1` / `cx23,cax11` | Where the archive lives; server types tried in order on placement errors only. |
| `ARCHIVE_SNAP_GB` / `ARCHIVE_BIG_GB` | 50 / 200 | Volume sizes at creation (10..=10240); grow with `archive resize`. Settable from the environment. |
| `ARCHIVE_KEEP_UNTIL` | unset | `YYYY-MM-DD`: the archive's retention date — README, `status` and `teardown --check` (`◷ kept`); nothing is ever deleted automatically. |
| `ARCHIVE_HOST` | the server's IPv4 | A DNS name for the participants' and pods' ssh configs (pushes use the pinned IP). |

## CLI ↔ TUI parity

TUI per-pod menu (`a`): test `[e]`, run `[x]`, set-branch `[g]`, backup `[b]`, setup `[p]`,
restart `[r]`, stop `[s]`, terminate `[t]` — lifecycle actions need the pod's name typed back
(restart is flagged as wiping the container disk on RunPod/Vast).
TUI fleet menu (`A`): the same minus stop; restart and terminate only for a **marked** set
(`/` + selector; `x` clears marks), which needs its count — or `ALL` for more than 5 pods or
the whole fleet — typed back. `d` deep-checks the cursor pod or the marked set in the
background; `n` adds pods. Every fleet datum (cost, maintenance badge, proxy port + state,
last health) comes from the same core `FleetSnapshot` as `arena snapshot`. A locked pod shows an
`L` badge (when no `M`), and restart/stop/terminate on it are refused with the unlock hint — the
TUI never unlocks (`arena pods unlock`).

Deliberately CLI-only (awkward or risky in a live dashboard): `up`/`create` placement flags,
`--api-json`, `lock`/`unlock`, `rename`/`reimage`/`replace`/`migrate`, `api get`, `run --background`/`jobs`/`logs`, `pull` (local file
IO), `copy-keys` (reads local CSVs), `cp`, `keys`, `ssh-config` (prints a file),
`snapshot --public`/`teardown --check`, `pods idle` and `balance`'s full table and `set` (the TUI shows the summary), `config`/`cron`/`plan`. In the TUI, stop stays
per-pod by design, and restart/terminate on many pods need an explicit marked set (no "stop
everything" footgun).
